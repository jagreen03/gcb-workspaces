# Objective

`TKT-019.18` widened the **control-plane abort backchannel's** identity
to `[session_nonce, epoch]` and proved, under a constructed adversarial
sequence, that this defeats a reset-boundary Ghost Abort. It did not
touch, and does not claim to have touched, the **data plane**:
`gcb_dwdm_deskew_cdc`'s own per-word acceptance test
(`epoch_match[c] = (head_epoch[c] == expected_epoch)`) has no session
scoping of any kind. This ticket determines whether that is a real,
exploitable gap, what would be required to close it, and whether the
control-plane fix's own mechanism (per-field tagging) is even the right
shape of fix for a structurally different kind of thing (a continuously-
queued data word, not a single control event). **No RTL is modified.
No candidate is assumed correct, sufficient, or necessary before being
shown so.** No PBG grade is assigned, consistent with
`TKT-019.6`/`.7`/`.12`-`.15`'s own precedent for architecture/trade-study
work.

---

## 1. Problem statement, confirmed by inspection, not assumed

`gcb_dwdm_deskew_cdc.sv`'s complete epoch-handling surface — `in_epoch`
(per-lane input), `expected_epoch` (output), `epoch_match`,
`epoch_discard`, `lane_ready` — was re-inspected for this ticket.
**None of it was touched by `TKT-019.16`, `.17`, or `.18`.** Those three
tickets modified only `gcb_dwdm_payload_mux.sv`'s abort-request path
(`abort_tx_valid`/`abort_tx_epoch`/`abort_tx_nonce`/
`current_session_nonce`) and the cocotb testbenches exercising it. The
module that actually decides whether a *data word* is current or stale
is unmodified and carries no session concept whatsoever.

**The restated vulnerability:** a data word genuinely in flight from a
prior session (physically delayed — stuck in an upstream buffer this
epic does not own, or arriving late through a slow, independently-
recovered per-lane clock domain), tagged with whatever `in_epoch` value
its sender used, which numerically equals `expected_epoch`'s value
immediately after a reset (always 0, unconditionally, per
`TKT-019.12`/`.13`'s own finding, unaffected by anything in `.16`-`.18`),
is **structurally indistinguishable** from a genuinely current word of
the first post-reset transaction. This is not a new mechanism — it is
the *data-plane sibling* of exactly what `TKT-019.18` closed on the
control plane, left open because nothing in that ticket's own scope
(correctly stated in its own §6/Out of Scope) reached this module.

## 2. Does the reset-boundary analysis already done elsewhere apply as-is?

**Partially, and the part that doesn't is the more dangerous part.**
`TKT-019.12`'s `D ≤ I` condition was derived for **ordinary, within-
session wraparound**: a buried word survives only if the epoch counter
completes one or more full laps (a multiple of `I = 2^EPOCH_W`) while
it waits. **Reset does not lap the counter — it resets it to a fixed
value outright, consuming zero wraps.** `TKT-019.13` §5 already proved
this exact point for the general case ("reset aliasing... requires
zero, not `2^EPOCH_W - 1`, further transactions"). Restated precisely
for this ticket's own scope: **the `D ≤ I` margin analysis does not
apply at a reset boundary at all — it is not merely insufficient
margin, it is the wrong analysis for this specific failure mode.**
Widening `EPOCH_W`, which at least delays ordinary wraparound, does
**nothing** here, for the same reason `TKT-019.13`/`.17`/`.18` already
established: every width restarts at the identical value 0 on reset.

## 3. Candidate mechanisms — compared, not selected

No candidate below is recommended. Each is evaluated on the same axes
this sub-chain has used throughout: correctness proof, cost, latency,
verification risk, proof burden, and — specifically for this ticket —
**whether the mechanism even fits the thing being protected** (a
continuously-queued data word is not a single control event, and a fix
shaped for one may not be the right shape for the other).

### A. Per-word session tag, mirroring `TKT-019.18`'s own mechanism

Widen the CDC's per-lane FIFO storage (`FDW = DW + EPOCH_W` today) to
`FDW' = DW + EPOCH_W + NONCE_W`, carrying a session nonce alongside
`in_epoch` for every word, compared alongside `expected_epoch` in the
same per-word check: `epoch_match[c] = (head_epoch[c] == expected_epoch)
&& (head_session[c] == expected_session)`.

* **Correctness proof:** strong, by the same construction `TKT-019.18`
  already validated for the control plane — a session mismatch rejects
  regardless of epoch alignment.
* **Cost:** real and quantifiable by the same method `TKT-019.9`/`.12`
  already used: `NUM_COLORS × DEPTH × NONCE_W` additional memory bits.
  At 16 bits (matching `TKT-019.18`'s own width) and the `NUM_COLORS=60,
  DEPTH=128` ceiling: `60 × 128 × 16 = 122,880` bits (≈15 KB) — **on top
  of**, not instead of, the epoch tag's own existing cost. This is pure
  memory-bit cost by the same Yosys-cell-counting precedent
  (`TKT-019.9`/`.11`), not a logic-cell cost.
* **The unresolved wire-format question this inherits, unchanged:**
  `TKT-019.9` ("the epoch tag never leaves the CDC, zero optical
  bandwidth") and `TKT-019.7` ("the epoch tag rides in every word,
  nonzero sideband cost") describe two different physical designs for
  the *existing* 4-bit epoch tag, still never reconciled
  (`TKT-019.12` §11.6, restated unresolved in `TKT-019.15` §8). Adding a
  second, wider per-word field inherits this same unresolved question —
  doubly so, since a session nonce is exactly the kind of field that
  *would* need to physically travel with the data if it is to be
  checked at the receiver at all (unlike the control-plane nonce, which
  a testbench/host can inject locally).
* **Verification risk:** moderate — same comparator shape as the
  existing epoch check, re-using `TKT-019.11`'s own adversarial test
  style directly.
* **Proof burden discharged:** the reset-aliasing gap specifically, for
  data words — nothing else.

### B. A live, CDC-side `current_session_nonce` input, unpaired with per-word tagging

Mirror the control-plane mechanism's *receiver-side* half only (a live,
host-driven input the CDC compares against) **without** adding a
per-word field to the data itself.

* **Does not work, and this is worth stating explicitly rather than
  silently avoiding it:** the control-plane abort message's nonce is
  meaningful because the message is generated by the **current**
  receiver decision, at the moment it is sent, carrying a value that
  can be compared at arrival. A data word has no such freedom — its
  `in_epoch` value was fixed by the **sender**, potentially a full
  session ago, with no receiver-side input involved in choosing it.
  There is nothing for a CDC-side-only nonce to compare *against* on
  the data path unless the data itself carries a matching field —
  which is candidate A. **B is not a standalone candidate; it is half
  of A, and does not close anything alone.** Recorded here specifically
  to rule it out explicitly, not to leave it looking viable.

### C. Reset-time physical drain/quiescence, strengthened

Rather than tagging data identity at all, guarantee by construction
that no pre-reset word can still be *physically present and reachable*
after reset completes — the same "retirement barrier" class `TKT-019.14`
§6/`TKT-019.15` §4 analyzed for the per-transaction case, applied here
specifically at the reset boundary.

* **What's already proven, reused, not re-derived:** `TKT-019.13` §9.1
  found that a reset asserted **simultaneously and with sufficient
  overlap across every domain** (the CDC's `rd_rst_n`, every lane's
  `wr_rst_n[c]`, and the 2-flop gray-code synchronizers on both sides)
  produces a consistent, pointer-verified empty state — this epic's own
  testbenches have always exercised exactly this simultaneous case, and
  it is `PROVEN — DIGITAL SIMULATION, TESTED CONDITIONS` for that case
  specifically.
* **What's still open, and is the actual gap:** whether every reset in
  a real deployment is genuinely simultaneous and sufficiently
  overlapping across **independently recovered per-λ clock domains**
  (the CDC's entire reason to exist, `TKT-019.3`) is an
  `ARCHITECTURAL ASSUMPTION`, never independently tested — `TKT-019.13`
  flagged this and no later ticket in this chain has tested it.
  `TKT-019.15` §4's falsification of `fifo_empty`-implies-safe (the
  synchronizer-lag argument) applies here too: a drain barrier at reset
  time needs the same care a per-transaction one would, not an
  automatic pass merely because it happens at reset.
* **Correctness proof:** potentially strong, but **contingent on
  closing the independent-per-lane-reset-timing question first** — not
  free, and not yet done.
* **Cost:** low if it works (reuses existing pointer/reset logic,
  genuinely no new per-word field) — the cheapest candidate here, if
  its contingent question resolves favourably.
* **Proof burden discharged:** potentially all of it, for reset
  specifically — but only once the independent-reset-timing question
  (not previously closed by any ticket in this chain) is answered.

### D. Persisted/non-wrapping generation marker, applied to the data plane's own `expected_epoch`

The `TKT-019.12` §10.4 / `TKT-019.13` §7 candidate, here applied to
`expected_epoch` itself (not `tx_epoch`/the control-plane nonce).

* **Same caveats, unchanged, not re-derived:** `TKT-019.13` §7's own
  finding that persistence failure silently reverts to the exact unsafe
  default applies identically here — a marker surviving reset for the
  *data plane's* own counter is not automatically safer than the
  *control plane's* equivalent, and inherits the identical new
  dependency (a persistence mechanism this architecture has never had).
* **Interacts with candidate A:** if adopted, this changes what A's
  `NONCE_W` needs to be wide enough for (practically-never-wrapping vs.
  `TKT-019.18`'s own 16-bit, session-scale choice) — not an independent
  decision from A, a parameter of it.

### E. Mandatory post-reset quiescence period, bounded by `T_stale_max`

Hold off accepting new traffic for a proven duration after reset.

* **Inherits `TKT-019.12` §7.H's own circularity finding directly, not
  a new instance of it:** `T_stale_max` for the data plane was already
  shown structurally circular (discard depends on further epoch
  advances, which is the quantity being bounded) — this candidate
  cannot be sized without first resolving that circularity, which
  remains `OPEN` from `TKT-019.12` onward, untouched by anything since.

## 4. What this ticket does NOT conclude

**A selection among A-E is not made.** The strongest-looking candidate
on paper (C, reset-time drain) is contingent on a question
(independent-per-lane reset timing) this epic has flagged since
`TKT-019.13` and never tested; the most directly analogous candidate to
`TKT-019.18`'s own proven mechanism (A) carries a real, nontrivial
memory-bit cost and inherits an unresolved wire-format question two
tickets old. Recommending one without testing C's contingency or
resolving A's wire-format question would be exactly the kind of
premature convergence this epic's own discipline exists to prevent.
