# Objective

`TKT-019.15` derived, on paper, that no currently-existing mechanism
establishes a provable transaction retirement boundary, and named the
missing sender-side abort/interrupt capability as the single decision
most worth resolving before any other candidate can even be evaluated.
This ticket builds and adversarially tests ONE candidate — sender-side
abort — as an actual RTL experiment, not a further paper analysis.

**This is an evaluation, not an adoption.** Sender abort is tested here
as one candidate mechanism for establishing a provable retirement
boundary; it is not assumed, and is not concluded at the end of this
ticket, to be the final architecture. Where the experiment finds the
mechanism insufficient (Task 7 Case F), that finding is reported and
held for disposition, per this epic's standing discipline — not
patched inside this same ticket. No PBG grade is assigned, consistent
with `TKT-019.6`/`.7`/`.12`/`.13`/`.14`/`.15`'s own precedent for
architecture/trade-study work — this ticket is closer to that family
than to a build story, despite containing real RTL, because its
deliverable is a falsification result, not a shipped feature.

## 3. Architectural hypothesis

> If the sender can be commanded to stop generating additional words
> belonging to transaction N, and the receiver can subsequently
> establish that all previously launched N state has drained, then a
> deterministic retirement boundary may be constructed.

Everything that must be true for this hypothesis to hold, distinguished
explicitly:

1. **Sender FSM quiescence** — the sender's own state machine must
   reach, and remain in, a state that produces no further output for
   the commanded-against generation. **Built and tested this ticket**
   (§4-§7).
2. **Sender-side pipeline drain** — any sender-internal storage
   (framed-word buffers, CRC accumulators, etc.) that might still hold
   or emit N's content after the command must be shown either empty or
   unreachable. **Addressed for this specific RTL** (§5) — `word_a_flat`/
   `word_b_flat` are shown safe by construction (always fully
   overwritten before their next read), not by being cleared.
3. **Transport propagation delay** — the command itself takes nonzero,
   currently-unbounded time to reach the sender (`TKT-019.15`'s
   `T_prop_fwd`) — **not built or bounded here**; this experiment
   models it as an explicit, swept testbench parameter, never claims a
   real value.
4. **Receiver CDC synchronization** — `TKT-019.15`'s own falsification
   of `fifo_empty` implying `N_stale==0` (synchronizer-lag component)
   — **unchanged, not re-examined or re-opened by this ticket.**
5. **Receiver FIFO drain** — the `D`-cycle cap on queued backlog
   (`TKT-019.11`/`.12`, `PROVEN`) — **unchanged, reused as-is.**
6. **Receiver reconstruction state** — the demux's own accumulation
   registers — **unchanged from `TKT-019.14` §5's finding** (self-
   healing on its own watchdog, structurally blind to CDC-side state).
7. **Control-plane propagation** — whatever carries the abort command
   itself must not be susceptible to the same identity-aliasing problem
   it exists to solve (`TKT-019.15` §6's anti-aliasing contract). **This
   is exactly where the experiment found the hypothesis's weakest link**
   (Task 7 Case F, §7 below) — not a component this ticket assumed away.
8. **Identity reuse** — deciding when the NEXT generation's tag may be
   assigned — **explicitly out of scope for this ticket** (the
   experiment uses a documented testbench-only poke to stand in for the
   not-yet-designed sender/receiver identity-sync mechanism, never
   claimed as real hardware behavior; see §6).

## 4. Candidate abort RTL

**Inspection before modification, per the task's own instruction:**
`gcb_dwdm_payload_mux`'s FSM is exactly two states, `{S_IDLE, S_EMIT}`.
`S_IDLE` only samples `start`; `S_EMIT` drives one word per cycle from
pre-built `word_a_flat`/`word_b_flat` arrays, checking
`cycle_idx == cycles_total_q - 1` to decide `done`/return-to-`S_IDLE`.
This is the only place emission decisions are made — the correct, and
only, insertion point for an abort check is at the top of the `S_EMIT`
case body, ahead of its existing per-cycle logic, checked once per
cycle. No other logic (CRC computation, word-array construction, the
`S_IDLE` branch itself) needed touching, and none was touched.

**Implemented** (`gcb_dwdm_payload_mux.sv`): new `input logic abort_tx`
and `output logic tx_quiescent`. Inside `S_EMIT`, `if (abort_tx)` is
checked FIRST, ahead of the existing per-cycle emit logic: when true,
every lane's `tx_color`/`tx_valid` is forced to `'0` for **this** cycle
(the would-be word, whether ordinary or the transaction's own final
word, is suppressed entirely — never partially driven then retracted),
and `state <= S_IDLE`. `done` is **not** reachable on this path, by
deliberate design (§4.1 below explains why). `tx_quiescent` is a plain
`assign tx_quiescent = (state == S_IDLE)` — see §5.

**Deliberately not built here, and not claimed:** `abort_tx` carries no
generation/epoch identity of its own, and does not itself advance
`tx_epoch`. Both omissions are explicit scope boundaries stated in the
RTL's own header comment, not oversights — §7's Case F demonstrates
exactly why the first omission matters.

### 4.1 One deliberate design decision, made and documented, not left implicit

**Abort takes priority over completion.** If `abort_tx` arrives on the
cycle that would otherwise emit the transaction's own final word, that
word is suppressed too, and `done` never fires — even though every
prior word of that transaction was correct. This is the conservative
choice: a receiver that has already decided to abort presumably has
already moved its own bookkeeping (e.g. `expected_epoch`) past this
generation, so the final word — however correct — would arrive tagged
with a value the receiver no longer expects, making its discard the
safe outcome regardless. Tested explicitly as Task 7 Case C (§7).

## 5. `tx_quiescent`, defined precisely

`tx_quiescent = (state == S_IDLE)`, equivalently `~busy`. **This is
not a new piece of independent state — the contribution of this ticket
is that the sender can now be COMMANDED into this state via
`abort_tx`, rather than only reaching it by running `S_EMIT` to its own
natural completion.** Checked against every sub-condition the task
asked about, each confirmed by direct RTL inspection, not assumed:

* **No pending output word** — true whenever `tx_quiescent`; the FSM's
  own sequencing (the only thing that ever drives `tx_color`/`tx_valid`)
  has stopped.
* **No registered output-valid** — `tx_valid` reads `0` by the same
  cycle `tx_quiescent` first reads `1` on the abort path (both are set
  in the same `if (abort_tx)` block, same edge) — confirmed empirically
  via direct signal trace during test development (§6), not merely
  read off the RTL text.
* **No serializer/packing state** — `word_a_flat`/`word_b_flat` retain
  whatever content the aborted (or completed) transaction last wrote;
  this is **safe by construction, not by being cleared** — the very
  next `start` unconditionally rewrites every entry of both arrays
  before `S_EMIT` is ever re-entered, so stale content is never read.
* **No transaction-final state pending** — `done` never asserts on the
  abort path (§4.1); no `is_tile_final` bit is ever latched for a
  suppressed word.
* **No additional sender-side pipeline state** — `cycle_idx`,
  `cycles_total_q`, `lane_enable_q`, `mode_b_q` are read only while
  `state == S_EMIT` and are all unconditionally overwritten at the next
  `start` — confirmed by inspection, no hazard found.

**What `tx_quiescent` explicitly does NOT establish — the exact
boundary the task asked to be stated, not glossed over:** it is a
**sender-local** claim only. It says nothing about propagation delay to
or from the sender, nothing about receiver-side CDC synchronization or
FIFO drain (`TKT-019.15`'s own falsification, unchanged), and nothing
about physical transport state downstream of this module's own output
registers — this repo has no RTL or model for the optical channel
`tx_color`/`tx_valid` would drive in a real system (the same boundary
`TKT-019.4` already stated, unchanged by this ticket).

## 6. Digital abort-race experiment

Built in `sim/cocotb/test_wdm_link_integration.py` against the real
`gcb_dwdm_payload_mux` → [cocotb Channel] → `gcb_dwdm_deskew_cdc` →
`gcb_dwdm_payload_demux` chain (the same chain `TKT-019.4`/`.5`/`.8`/`.10`/
`.11` already exercise), with `abort_tx`/`tx_quiescent` newly wired
through `wdm_link_integration_tb_top.sv`. `T_prop_back` is modelled as
an explicit, swept number of `clk` cycles between the CDC's own
`cdc_txn_void` firing and `abort_tx` being delivered to the sender —
**never claimed as a measured or bounded physical quantity**, exactly
`TKT-019.15` §5's `T_prop_back` term, used here only as a controlled
testbench input.

`test_sender_abort_retirement_race`: transaction N (Mode B, 1024 B,
all 60 lanes), lane 30 permanently withheld from the channel — the
CDC's own `ALIGN_TIMEOUT`-gated watchdog fires `cdc_txn_void` for real
(receiver-side failure detection, not a testbench shortcut). Swept
`T_prop_back ∈ {0, 5, 20, 64, 128}` cycles after `cdc_txn_void`, then
`abort_tx` delivered, `tx_quiescent` confirmed, the receiver's now-
stale backlog drained (via the already-`PROVEN` `epoch_discard` path,
`expected_epoch` already advanced by `txn_void` itself), then N+1
(fresh 1024 B, all 60 lanes, no fault) begun and checked byte-exact.
**Result: `PASS` at every `T_prop_back` tested — N+1 reconstructed
byte-exact, zero contamination from N, at every delay.**

**An honest finding, measured rather than assumed going in:** at this
testbench's own geometry (`ALIGN_TIMEOUT=64`, Mode B 60-lane
1024 B), `gcb_dwdm_payload_mux`'s own worst-case Mode B emission
completes in **2 cycles** (60 lanes running in parallel), which is
trivially shorter than the receiver's 64-cycle failure-detection
window. **The sender is already naturally quiescent, via ordinary
`done`, long before any abort — at any `T_prop_back ≥ 0` measured from
`txn_void` — could possibly arrive.** Every one of the five swept
delays in this test therefore exercises the same already-covered
no-op path (Task 7 Case D), not a genuine "catch it mid-emission" race.
This is reported because it was measured, not assumed: it directly
illustrates `TKT-019.15` §5's point that `T_quiesce` is bounded by the
sender's own transaction length, and for a short, wide Mode B
transaction that bound is trivially small relative to the receiver's
own multi-tens-of-cycles detection latency — **the race this part of
the experiment set out to look for does not exist at this specific
geometry**, which is itself the reportable result, not a test defect.

## 7. Adversarial cases

| case | scenario | result |
|---|---|---|
| **A** | abort before the first payload word (Mode A, 271 B, `cycles_total=18`) | **PASS** — 0 words emitted, `done` never asserted, `tx_quiescent` on the first checked edge |
| **B** | abort mid-transaction (after 9 of 18 words) | **PASS** — exactly 9 words emitted, `done` never asserted |
| **C** | abort arrives ON the final payload word | **PASS**, confirming §4.1's design decision precisely — exactly 17 of 18 words emitted (the final one suppressed too), `done` never asserted |
| **D** | abort arrives immediately AFTER the final word (transaction already completed naturally) | **PASS** — confirmed complete no-op: `tx_epoch` unchanged, sender remains quiescent |
| **E** | multiple abort indications (held/re-pulsed across 5 idle cycles after quiescence) | **PASS** — idempotent, no re-trigger, no spurious re-entry into `S_EMIT`; a subsequent clean transaction is unaffected |
| **F** | delayed abort from N arrives after N+1 begins | **FAILED — CONFIRMED ADVERSARIAL FINDING, not a regression against any claim this ticket made.** See below. |
| **G** | sender reset while abort is outstanding | **PASS** — reset wins outright, `tx_epoch` correctly restored to 0, no glitch, normal operation resumes cleanly |

### Case F — the single most consequential result in this ticket

`test_abort_late_delivery_aliases_next_transaction`: transaction N
completes entirely cleanly (no fault of any kind). N+1 begins
immediately after and is still mid-emission when a **stale** `abort_tx`
— originally meant for N, delayed this whole time by an (unmodelled,
slow) backchannel — finally arrives. **Confirmed: N+1 is incorrectly
aborted.** `tx_quiescent` asserts, `done` never fires for N+1, and an
entirely unrelated, in-progress, otherwise-correct transaction is
silently discarded.

**This is not a bug found by accident — it is the exact mechanism
`TKT-019.15` §6 derived on paper** ("a bare, untagged control signal
reconstructs the identity-aliasing problem one layer up"), now
**demonstrated in actual RTL behaviour**, not merely argued. Per this
epic's standing discipline, **it is reported and held for disposition,
not patched inside this ticket** — patching it here (e.g. by bolting on
a generation-tag check) would silently promote an ad hoc fix to
ratified architecture, exactly what `TKT-019.6`/`.7`/`.12`-`.15`'s own
discipline exists to prevent. The requirement this exposes, precisely:
**any backchannel signal built from this experiment must carry the
full anti-aliasing tuple `TKT-019.15` §6 derived** (session/generation
id, message type, transaction id, sequence number, receiver-side state
validation) — a bare level signal is insufficient by construction,
exactly as predicted, now confirmed.

## 8. Retirement claim — exact boundary

**Not claimed:** `tx_quiescent && fifo_empty == physical proof of
N_stale == 0`. This ticket does not walk back `TKT-019.15`'s own
falsification of that implication (synchronizer-lag component,
receiver-side) — nothing here touches the receiver's own
`fifo_empty`/`epoch_discard` logic at all.

**What this digital experiment actually establishes, precisely:**

* `PROVEN — DIGITAL SIMULATION, TESTED CONDITIONS`: `gcb_dwdm_payload_mux`
  can be commanded, via a single new input, into a well-defined,
  sender-local quiescent state, correctly and immediately (same-edge,
  once the signal's own write-timing is respected — §6's toolchain
  notes) suppressing further output for the targeted generation, across
  every FSM-timing boundary tested (Cases A-D), under repeated/held
  assertion (Case E), and across a reset race (Case G).
* `CONFIRMED ADVERSARIAL FINDING`: this mechanism, as built (a bare,
  untagged level signal), is **insufficient** as a complete retirement
  boundary — Case F shows it can misfire against an unrelated later
  transaction if delivered late, which is exactly the control-plane
  aliasing risk a genuine backchannel would need to avoid.
* **Explicitly unmodelled, and not claimed physically validated by
  anything in this ticket:** propagation delay through any real
  backchannel medium (`TKT-019.15` §6's four candidates, still none
  selected); the optical channel `TKT-019.4` already declared out of
  scope; any implementation state in a real ASIC beyond what this
  RTL's registers represent.

**Net effect on the hypothesis (§3):** items 1 and 2 (sender FSM
quiescence, sender-side pipeline drain) are now `PROVEN` for this
specific RTL. Item 7 (control-plane propagation) is now `CONFIRMED
INSUFFICIENT` in its simplest form, narrowing — not widening — the
space of mechanisms that could complete the hypothesis. Items 3-6 and 8
are unchanged from `TKT-019.15`.

## 9. Comparison against alternatives

Brief, per the task's own scope — a full trade study is not repeated
here (see `TKT-019.14` §10 / `TKT-019.15` §8 for the exhaustive
version); this section places THIS ticket's actual, tested result
against each.

* **Receiver quarantine** — does not require modifying the sender at
  all, but per `TKT-019.15`'s own analysis still needs a proven
  drain-completion condition; Case F's finding applies with equal force
  to whatever signal triggers quarantine-exit if it is not itself
  tagged — this experiment's central finding is not specific to
  sender-side mechanisms.
* **Explicit transaction retirement ACK** (`TKT-019.14` §3.5's
  handshake model) — would very likely have **prevented** Case F's
  exact failure, since a negotiated-per-transaction protocol inherently
  ties every message to a specific, mutually-agreed transaction
  (disagreement blocks progress rather than silently aliasing, per
  `TKT-019.14`'s own analysis). This experiment's Case F result is now
  a **concrete, RTL-demonstrated** argument for that property, not only
  a paper one.
* **Sender-side transaction fencing** — essentially "this ticket's
  mechanism plus the anti-aliasing tuple `TKT-019.15` §6 derived" — the
  natural next iteration on what was actually built here, not a
  materially different mechanism.
* **Drain-before-identity-reuse** (`TKT-019.14`/`.15`'s own preferred
  direction) — an orthogonal axis: sender abort (this ticket) governs
  when the sender **stops**; drain-before-reuse governs when the
  receiver considers it **safe to move on**. This experiment's
  mechanism is a plausible **component** of such a scheme, not a
  competing alternative to it.

**Final State:** `open | pending`. Sender abort is `PROVEN — DIGITAL
