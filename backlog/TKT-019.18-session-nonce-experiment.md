# Objective

`TKT-019.17` neutralized the within-session Ghost Abort (`TKT-019.16`
Case F) by tagging the backchannel with `tx_epoch`. Its own closing
observation named the gap that check leaves open: `tx_epoch`
unconditionally restarts at 0 on reset (`TKT-019.12`/`.13`'s own
finding), so a delayed abort tagged epoch=0 from a **prior** session
numerically aliases the **first post-reset transaction's own epoch=0**.
This ticket expands the identity tuple to `[session_nonce, epoch]` and
runs the Reset Ghost Abort Experiment to test whether that specific
aliasing is defeated. **This is a targeted fix for the one reset-
boundary gap `TKT-019.17` itself identified, not a claim that the
broader identity-authority, reset-generation-semantics, or backchannel-
medium questions `TKT-019.13`/`.14`/`.15` left open are now closed.**
No PBG grade is assigned, consistent with this sub-chain's precedent.

---

## 2. Architectural hypothesis

> If transaction identity is expanded to include a `session_nonce`
> that is globally unique across resets, and the control-plane
> backchannel tags all aborts with this tuple, then delayed control
> messages from a prior session cannot alias transactions in a new
> session, regardless of `epoch` overlap.

**What this ticket tests, precisely:** the *comparison mechanism* -
given two different `session_nonce` values, does the sender correctly
refuse to honour an otherwise-epoch-matching abort. **What this ticket
does not test or claim:** that a 16-bit width is *sufficient* against
collision for a real deployment, or that any particular nonce-
issuance *policy* (a persisted, monotonic counter that survives power
loss vs. a value drawn fresh each session) is itself correct. `TKT-019.13`/
`.15`'s own caution against mistaking a probabilistic collision
argument for a structural safety proof applies unchanged here - "globally
unique across resets" in the hypothesis above is the premise this
experiment is built on top of, not something the experiment itself
establishes. The host's own nonce-issuance policy is explicitly out of
scope (§5).

## 3. RTL implementation

**`gcb_dwdm_payload_mux.sv`:** two new inputs, `current_session_nonce
[15:0]` and `abort_tx_nonce [15:0]`. `current_session_nonce` is
**deliberately not latched or reset by this module** - it is an
external, host/CSR-driven value the module simply reads live; there is
nothing for it in the `if (!rst_n)` branch. This is the property that
lets a post-reset session reject a pre-reset session's stale abort even
though `tx_epoch` itself has no memory of the reset having happened.
The `S_EMIT` abort check widens from `TKT-019.17`'s
`abort_tx_valid && (abort_tx_epoch == tx_epoch)` to additionally require
`(abort_tx_nonce == current_session_nonce)` - a Ghost Abort is now
anything failing *either* field, not just the epoch.

`bash sim/lint.sh`: exit 0, **36/36 tops clean** (unchanged count).

## 4. Testbench upgrade

`sim/cocotb/wdm_link_integration_tb_top.sv` and
`wdm_payload_mux_tb_top.sv` (the latter tied to inert `'0` defaults,
unexercised, as with `TKT-019.17`) carry the two new ports through to
the mux instance. `sim/cocotb/test_wdm_link_integration.py`: a new
module constant `DEFAULT_SESSION_NONCE` is driven as *both*
`current_session_nonce` and `abort_tx_nonce` by `_reset()` - every
test that never deliberately diverges the two (i.e. every test through
`TKT-019.17`, unchanged) implicitly runs under one single, matching
session throughout, exactly as if this check did not exist. No other
existing test needed to change.

A new helper, `_mid_test_system_reset`, was added specifically because
the shared `_reset()` helper **starts a fresh set of `Clock()` tasks**
on `dut.clk`/every `c{i}_wr_clk` every time it is called - calling it a
second time mid-test (needed for this experiment's own Task 5 step 5)
would have started a second, independent clock driver on top of the
one already running, the exact cross-test clock-driver contamination
class `TKT-019.11` found and fixed. `_mid_test_system_reset` toggles
`rst_n`/every `wr_rst_n` on the already-running clocks instead.

## 5. The Reset Ghost Abort Experiment

`test_reset_ghost_abort_rejected_by_session_nonce`, run exactly per
Task 5's ten steps:

1. Host sets `current_session_nonce = SESSION_A` (`0xAAAA`).
2. Transaction N starts (Mode B, all 60 lanes) - nonce `SESSION_A`,
   epoch 0.
3. Lane 30 withheld - the CDC's **own** `ALIGN_TIMEOUT` watchdog fires
   `cdc_txn_void` for real (not a testbench shortcut); the receiver's
   backchannel would tag an abort `[SESSION_A, epoch=0]` for N.
4. That abort is constructed but **deliberately not delivered** -
   held, "in the transport."
5. A genuine mid-test system reset (`_mid_test_system_reset`) fires -
   `tx_epoch` restored to 0, the **same** numeric value N already had.
6. Host establishes a new session: `current_session_nonce = SESSION_B`
   (`0xBBBB`).
7. The sender begins the first post-reset transaction - epoch 0
   (unavoidably, by construction), session `SESSION_B`.
8. The delayed, pre-reset abort `[SESSION_A, epoch=0]` arrives.
9. Verify rejection.
10. Verify the post-reset transaction completes byte-exact.

**Result: `PASS`.** The epoch half of the stale abort numerically
matched (`0 == 0`, confirmed by assertion, not merely assumed) -
exactly the aliasing condition this experiment exists to construct -
but the session-nonce half did not (`0xAAAA != 0xBBBB`), and the
sender correctly stayed `busy`/non-`tx_quiescent` throughout delivery.
The post-reset transaction reconstructed byte-exact, undisturbed.

**A real debugging finding worth recording, not a signal-timing
quirk this time:** the first version of this test used a 1024 B Mode B
payload for the post-reset transaction and failed - not because the
anti-aliasing check was wrong, but because a 1024 B Mode B transaction
at this tb_top's 60-lane geometry completes in just **2 cycles**
(`TKT-019.16` Task 6's own already-measured finding, reproduced here
by accident before being recognized): the transaction completed
**naturally** before the test's own setup overhead (spawning the
capture task, priming the abort fields) had finished, so the observed
"abort" was actually the genuine, unrelated `done` pulse advancing
`tx_epoch` to 1 - the test was not exercising the condition it claimed
to. Switched to a Mode A, single-lane, 271 B payload
(`cycles_total = 18`, matching the FSM-boundary tests' own established
choice) to give adequate headroom, confirmed the transaction was
genuinely still `busy` when the abort arrived, and re-ran clean.

Full regression: `TESTS=17 PASS=17 FAIL=0` (16 prior tests unaffected +
this one new test), re-run twice for determinism. Standalone
`Makefile.wdm_payload_mux` suite unaffected: `TESTS=3 PASS=3`.

## 6. Out of scope — what this ticket does not close

1. **The host's own nonce-issuance policy** - whether
   `current_session_nonce` is a persisted, monotonically-incrementing
   value that survives power loss, or a value drawn fresh each session
   (and by what mechanism), is not designed or tested here. `TKT-019.13`
   §7's own analysis of persisted-generation failure modes (silent
   reversion to the unsafe default if the persistence mechanism itself
   fails) applies to whatever policy is eventually chosen, unchanged.
2. **Width sufficiency** - 16 bits is what this experiment implements,
   per the task's own specification; no collision-probability
   argument is made or implied for any real deployment.
3. **Identity authority** (`TKT-019.13`/`.14` §3) - still unresolved;
   `tx_epoch` does not auto-advance on any matching abort, unchanged
   from `TKT-019.16`/`.17`.
4. **The remaining anti-aliasing tuple fields** (`TKT-019.15` §6) -
   message type, sequence/order information, and receiver-side state
   validation remain undesigned.
5. **A real physical backchannel medium** (`TKT-019.15` §6) and
   **`gcb_dwdm_transceiver_top` integration** - unchanged, both still
   open/additive respectively.
6. **Simultaneous vs. one-sided reset** (`TKT-019.13` §9.1) - this
   experiment resets the whole tb_top (mux, CDC, demux) together via
   one shared `rst_n`/`wr_rst_n` set, matching every prior test in this
   file; the independent-per-lane-reset-timing case that ticket flagged
   as an untested `ARCHITECTURAL ASSUMPTION` remains untested here too.

## Telemetry & Evaluation

No PBG grade assigned, consistent with this sub-chain's precedent -
`current_session_nonce`/`abort_tx_nonce` remain unwired into the real
transceiver top.

**Final State:** `open | pending`. The specific reset-boundary Ghost
Abort `TKT-019.17` predicted is neutralized by the widened
`[session_nonce, epoch]` comparison, under a constructed aliasing
condition (genuinely matching epoch, mismatched nonce) confirmed by
assertion, not assumed. This closes one specific, anticipated gap - it
does not close the host nonce-issuance policy, identity authority, the
remaining anti-aliasing tuple fields, or backchannel medium selection,
all of which remain exactly as open as `TKT-019.13`/`.14`/`.15` left
them.

**Recommended next action:** the natural next falsification target is
the nonce-issuance policy itself (§6 item 1) - specifically, what
happens if `current_session_nonce` is reused across two sessions
(e.g. a persisted counter that wraps, or two devices independently
drawing the same "random" value) - `TKT-019.13` §7's persisted-
generation failure-mode analysis was written before this mechanism
existed in RTL and has not been re-tested against it.
