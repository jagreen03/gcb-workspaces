# Objective

`TKT-019.16` Case F **confirmed, in actual RTL behaviour**, the exact
risk `TKT-019.15` §6 derived on paper: a bare, untagged `abort_tx`
signal is vulnerable to the same temporal aliasing as the data plane — a
stale abort meant for a retired transaction N, delivered late, silently
terminated an unrelated, in-progress N+1 (the "Ghost Abort"). This
ticket implements the Control-Plane Anti-Aliasing Contract `TKT-019.15`
§6 specified, and re-runs `TKT-019.16`'s own adversarial construction
under it to confirm the Ghost Abort is neutralized. **This is a
targeted fix for one confirmed defect in an experimental mechanism, not
a claim that sender abort is now the ratified architecture** — the
remaining open items from `TKT-019.13`/`.14`/`.15` (identity authority,
reset-generation semantics, a real physical backchannel medium) are
unaffected and unaddressed by this ticket. No PBG grade is assigned,
consistent with this sub-chain's own precedent.

---

## 2. The Control-Plane Anti-Aliasing Contract

1. The receiver must append the `expected_epoch` to any `txn_void` or
   abort message sent to the sender.
2. The sender must compare the incoming `abort_tx_epoch` against its
   active `tx_epoch`.
3. If they match, the sender processes the abort and enters
   `tx_quiescent`.
4. If they do NOT match, the sender must silently discard the control
   message as a stale Ghost Abort.

This is exactly the tuple `TKT-019.15` §6 derived as necessary
(generation identity, checked against the recipient's own current
state) applied specifically to the abort signal — **not** the full
five-field tuple that ticket described for a general-purpose reliable
backchannel (session id, message type, sequence number, and
receiver-side state validation remain unimplemented; see §5 Out of
Scope). This ticket closes the one gap `TKT-019.16` actually
demonstrated failing, not the entire backchannel-design space `TKT-019.15`
mapped out.

## 3. RTL implementation

**`gcb_dwdm_payload_mux.sv`:** `abort_tx` replaced with
`abort_tx_valid` (unchanged in spirit — a level input, meaningful only
while `busy`) and a new `abort_tx_epoch [EPOCH_W-1:0]` input. Inside
`S_EMIT`, the check that used to be `if (abort_tx)` is now
`if (abort_tx_valid && (abort_tx_epoch == tx_epoch))` — the anti-
aliasing check itself, not a separate gate bolted in front of the
existing logic. A Ghost Abort (`abort_tx_valid` high, epoch mismatched)
falls straight through to the `else` branch — the ordinary per-cycle
emit logic proceeds completely unaffected, exactly as Contract item 4
requires (**silently discarded**, not merely flagged). Every other
`TKT-019.16` design decision is unchanged: abort still takes priority
over completion when it DOES match (Case C, unchanged); `tx_epoch`
itself is still not advanced by this path (identity-authority remains
explicitly out of scope, per `TKT-019.14` §3.4).

`bash sim/lint.sh`: exit 0, **36/36 tops clean** (unchanged count —
no new module).

## 4. Testbench upgrade and Case F re-run

`sim/cocotb/wdm_link_integration_tb_top.sv` and
`wdm_payload_mux_tb_top.sv` (the latter pre-existing, `TKT-019.2`/`.8`-
owned, tied to inert defaults, unexercised) updated to carry
`abort_tx_valid`/`abort_tx_epoch` through to the mux instance.
`sim/cocotb/test_wdm_link_integration.py`: every `TKT-019.16` abort
call site now tags its request with the transaction's own `tx_epoch`
(read at the moment of assertion, since `tx_epoch` is stable
throughout one transaction's own emission) — Cases A-D, E, G all
continue to exercise **correctly-matching** requests, since those
tests are about FSM-timing boundaries and repeated/reset behaviour, not
the anti-aliasing check itself.

**Case F re-run**, renamed `test_abort_late_delivery_rejected_as_ghost_abort`
to reflect the new expected outcome, under the **identical adversarial
construction** `TKT-019.16` used (not a weaker one): transaction N
(64 B, Mode A) completes entirely normally; N+1 (a different 64 B
payload) begins immediately after and is confirmed mid-emission
(`busy`, correct advanced `tx_epoch`) when a stale abort — tagged with
`n_epoch`, N's own (now-superseded) epoch, exactly what a real
backchannel would have captured at the time it was sent — arrives.

**Result:**

* `n1_epoch != n_epoch` confirmed (`tx_epoch` genuinely advanced
  between N and N+1 — the mismatch this test constructs is real, not
  assumed).
* The stale, `n_epoch`-tagged abort arrives mid-N+1 (`tx_epoch` now
  reads `n1_epoch`) — **`busy` stays asserted, `tx_quiescent` stays
  deasserted** — the Ghost Abort was correctly rejected, not merely
  tolerated by accident.
* N+1 reconstructs **byte-exact**, undisturbed by the rejected request.
* Full regression: `TESTS=16 PASS=16 FAIL=0` (all 11 pre-`TKT-019.16`
  tests, all 5 `TKT-019.16` FSM-boundary/reset/multiple-indication
  tests re-tagged and re-verified, and the re-run Case F), re-run twice
  for determinism. Standalone `Makefile.wdm_payload_mux` suite
  unaffected: `TESTS=3 PASS=3` (abort ports tied to inert defaults,
  never exercised by that suite).

**`TKT-019.16`'s own finding is not walked back by this passing
result.** That ticket correctly found the *untagged* mechanism
insufficient — Case F's original failure stands as the accurate record
of what an untagged `abort_tx` does. This ticket demonstrates that the
*tagged* mechanism closes exactly that gap, under the same adversarial
construction, and is a distinct, later result, not a correction to the
earlier one.

## 5. Out of scope — what this ticket does not close

Restated precisely, since it would be easy to over-read a passing Case
F re-run as more than it is:

1. **Identity authority** (`TKT-019.13`/`.14` §3) — still unresolved.
   This ticket implements the *comparison*, not a decision about who is
   authoritative or how the sender and receiver stay in lockstep in
   general (`tx_epoch` still does not auto-advance on a genuine,
   matching abort — unchanged from `TKT-019.16`).
2. **Reset-generation semantics** (`TKT-019.13` §5/`TKT-019.15` §7) —
   `tx_epoch` still resets unconditionally to 0; a pre-reset Ghost
   Abort tagged with a post-reset-reused value would still pass this
   comparison. Not addressed.
3. **A real physical backchannel medium** (`TKT-019.15` §6) — this
   ticket's "backchannel" remains the same cocotb-level abstraction
   `TKT-019.16` used; no propagation delay, reliability, or ordering
   guarantee is modelled beyond the explicit `T_prop_back` sweep
   already present in `test_sender_abort_retirement_race`.
4. **The full five-field anti-aliasing tuple** (`TKT-019.15` §6) — only
   the generation-identity field is implemented. Message type,
   sequence/order information, and receiver-side state validation
   remain undesigned; a future control message type beyond plain abort
   (e.g. a success ACK) would need its own instance of this same
   pattern, not inherit it for free.
5. **`gcb_dwdm_transceiver_top` integration** — `abort_tx_valid`/
   `abort_tx_epoch` remain additive, experimental ports, not wired into
   the real transceiver top.

## Telemetry & Evaluation

No PBG grade assigned, consistent with this sub-chain's own precedent
(architecture/experiment work, not a shipped feature — `abort_tx_valid`/
`abort_tx_epoch` remain unwired into the real transceiver top).

**Final State:** `open | pending`. The Ghost Abort `TKT-019.16` Case F
confirmed is neutralized under the identical adversarial construction,
by the generation-tagged comparison this ticket implements. This
closes one specific, demonstrated defect — it does not close identity
authority, reset-generation semantics, or backchannel medium selection,
all of which remain exactly as open as `TKT-019.13`/`.14`/`.15` left
them.

**Recommended next action:** the natural next falsification target is
whether a **reset-boundary** Ghost Abort (a stale request tagged with a
pre-reset epoch value that has since been reused post-reset) can still
alias — `TKT-019.13` §5/`TKT-019.15` §7's reset-generation gap applies
to this comparison exactly as it applies to the data plane's own
`word.epoch == expected_epoch` check, and has not been tested here.
