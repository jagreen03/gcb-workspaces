# Objective

**Re-prioritised ahead of TKT-019.2 (payload muxing) — Architect directive:
attack the physical receiver bottleneck before writing the logical
abstraction.**

Architect and parameterise the DWDM **deskew FIFO depth** and the
**clock-domain-crossing (CDC) architecture** of `gcb_dwdm_deskew` to support
the **≥ 60 λ Mode B** transport regime the ratified [[GCB-034]] Dual-Regime
Contract requires. This is a **characterisation story under the Orange
method** ([[TKT-000]]): measure the physical skew envelope and the CDC
requirement *before* committing a FIFO depth or a synchroniser architecture —
do not guess a number and back-fill a justification.

## Hard input constraint — the Dual-Regime Contract is NOT altered

Per the PM + Architect close of [[GCB-034]] and the [[GCB-037]] link budget:

* **Mode B** (K-split + INT32 partials) carries a **1024 B `acc_tile`** per
  K-split link, and at `P = 4` the accumulator node's inbound traffic spans
  **≈ 60 λ** (a near-full C-band comb at the assumed 2-PAM/QPSK + KP4 line
  rate).
* This story treats **1024 B / ≈ 60 λ as a fixed input**, not a variable.
  Nothing here may change the payload, the precision (D2), the granularity
  (D3), or the mode-selection logic (D4) ratified in [[GCB-034]].
* The deliverable is **receiver-side plumbing** — FIFO depth, CDC, failure
  handling — sized to carry that fixed traffic, not a re-negotiation of it.

## Current state — `gcb_dwdm_deskew`, as it stands today

| property | today | gap vs. the ≥ 60 λ Mode B regime |
|---|---|---|
| `NUM_COLORS` | parameter, default **8** (already proven to elaborate clean at 60, [[TKT-019.1]]) | count scales cleanly; **depth and clocking do not** |
| `MAX_SKEW_CYCLES` (FIFO depth) | parameter, default **16** | chosen for the original 2–8 colour link; **never derived from a measured skew envelope** |
| clock domains | **one** — `gcb_dwdm_skew_fifo` is a single-clock synchronous FIFO; the barrier (`aligned_valid`) pops all colour FIFOs on the *same* clock edge | **no CDC logic exists anywhere in this module.** If each λ's receiver recovers its own clock (the usual case for independent per-λ O/E + CDR in an IM-DD WDM link), this single-clock assumption is not just under-sized, it is **architecturally wrong** |
| failure handling | `overflow` (sticky, one bit, all colours OR'd) + `stall` (backpressure to the host packager) | a dropped word silently disappears (`wr_en & ~full` simply suppresses the write); **no retry, no fallback, no per-colour fault isolation**, and backpressure cannot recall light already in flight |
| payload width `DW` | `$bits(color_word_t)` = **136 b** (`packed_a` 64 + `packed_b` 64 + `wavelen_id` 6 + `is_tile_final` 1 + `valid` 1) | fixed by the contract; drives the area arithmetic below |

## Physical characterisation required

Five measurements, in order — each blocks the next.

### 1. Per-lane skew envelope

**The two candidate skew sources are NOT the same magnitude, and the story
must determine which dominates before sizing anything:**

* **Chromatic dispersion (CD), fibre-length-dependent.** SMF-28-class
  `D ≈ 17 ps/(nm·km)`. A 64-channel, 50 GHz-grid C-band comb spans
  `Δλ ≈ λ²·Δf/c ≈ 25.2 nm` (63 × 50 GHz at 1550 nm). At the **short-reach,
  co-packaged / rack-scale interconnect** [[GCB-037]] assumed (< 50 m):
  `Δt = D·Δλ·L ≈ 17 × 25.2 × 0.05 ≈ 21 ps` — **negligible**, well under one
  clock cycle at 1 GHz and likely sub-cycle even at a multi-GHz SerDes clock.
* **Inter-lane receiver / CDR skew, length-independent.** Each λ's O/E front
  end + independent clock/data recovery locks on its own schedule; lane-to-lane
  skew budgets in comparable multi-lane optical/electrical interfaces run from
  **tens of ns up to ~180 ns** (order-of-magnitude, by analogy to multi-lane
  SerDes skew specs) — **this is an estimate pending the PIC receiver / CDR
  spec, not a measurement.** If this is the dominant term, it is **3–4 orders
  of magnitude larger than CD** and is what actually sizes the FIFO.
* **Required validation:** confirm which term dominates from the intended PIC
  receiver architecture (`gcb-pic-core` / TKT-018 territory) before picking a
  `MAX_SKEW_CYCLES`. Do not default to the CD number because it is the
  easier one to compute.

### 2. Required FIFO depth

```
MAX_SKEW_CYCLES  >=  ceil( skew_envelope_ns / t_clk_ns )  +  margin
```

Two scenarios bound the answer until (1) is settled:

| scenario | skew envelope | at `t_clk = 1 ns` (1 GHz) | vs. today's default (16) |
|---|---:|---:|---|
| **CD-dominated** | ≈ 21 ps | `MAX_SKEW_CYCLES ≈ 1` (+ margin → the current 16 is already generous) | no change needed |
| **CDR/electrical-dominated** (estimate) | tens of ns | `MAX_SKEW_CYCLES` in the **32–180+** range, *pending spec* | **2–11× deeper**, TBD |

The story's output is not "pick one" — it is the **validated number**, sourced
to the receiver architecture in (3).

### 3. CDC architecture — the central undetermined decision

**Two architectures give completely different answers, and the existing RTL
has silently assumed one of them without saying so:**

* **(A) Shared / forwarded reference clock.** All λ receivers slave to one
  distributed clock (e.g. a pilot tone, a dedicated clock wavelength, or a
  common electrical reference). **No CDC is needed** — `gcb_dwdm_deskew`'s
  existing single-clock-domain design is architecturally correct; only the
  FIFO *depth* and *instance count* need to scale.
* **(B) Independent per-λ clock/data recovery.** Each of the (up to 60+)
  receivers recovers its own clock from its own optical data, independently.
  **CDC is mandatory** — the deskew stage must cross ~60 independent clock
  domains into the core domain *before or during* the barrier-align, typically
  via per-lane asynchronous FIFOs (gray-coded pointers, dual synchronised
  pointer crossings) rather than the current synchronous `gcb_dwdm_skew_fifo`.
* **This choice is not yet made anywhere in the repo.** `gcb_dwdm_deskew` was
  built assuming (A) without stating it as a decision. **Required output:**
  state which architecture the fabric commits to (or that both must be
  supported, mode-selected like [[GCB-034]] D4), and if (B), size the
  synchroniser stages (2-flop minimum per crossing) and the resulting MTBF
  budget as the **λ count scales the number of independent crossings**, not
  just the per-lane probability.

### 4. Worst-case buffering — area / power impact

Flop-based storage, `DW = 136 b` fixed by the contract:

| config | colours | depth | storage | vs. today |
|---|---:|---:|---:|---:|
| today's default | 8 | 16 | `8·16·136 = 17 408 b` ≈ **2.18 KB** | — |
| **NUM_COLORS=60, depth unchanged** | 60 | 16 | `60·16·136 = 130 560 b` ≈ **16.3 KB** | **7.5×** (count alone) |
| **NUM_COLORS=60, CDR-dominated depth (est. 64)** | 60 | 64 | `60·64·136 = 522 240 b` ≈ **65.3 KB** | **30×** |
| + CDC (scenario B) | 60 | (as above) | + gray-code pointer logic and **2 synchroniser flops per pointer, per crossing, ×60** | additional, not yet quantified |

**This is the same physical hazard [[GCB-032]] already measured, at channel
scale:** a wide bank of registers driven in parallel every cycle sits near the
max-transition edge on this node (GCB-032's 38 DRVs, at a single 64-flop-class
bank). **60 parallel deskew FIFOs, each its own `DW=136 b` write port toggling
every cycle, is the same physical pattern multiplied ~60×.** The story must
carry this forward as a DRV / floorplan risk, not assume it elaborates cleanly
just because it simulates cleanly (as [[TKT-019.1]]'s Yosys check only proves
latch-freedom, not timing closure).

### 5. Failure behaviour when a lane exceeds the deskew window

**Today: the failure is silent and the transaction is unrecoverable.**

* `gcb_dwdm_skew_fifo`'s `do_wr = wr_en & ~full` means a word arriving at a
  full FIFO is **simply dropped** — no error value, no marker on the dropped
  word itself. The module-level `overflow` is a single sticky bit **OR'd
  across all colours** — it tells software *that* something overflowed,
  never *which* colour or *which* transaction.
* **One optical transaction needs every participating λ.** [[GCB-034]]'s
  contract is one tile / one K-split partial per transaction; losing one
  colour's word corrupts the *whole* transaction (the `S_ij`/`Y` or
  remote-accumulate math has no partial-credit path). `stall` (backpressure)
  only prevents *future* overflows — it cannot recover data already lost, and
  it throttles the *electrical* host side, which cannot un-send light already
  in flight on the other 59 colours.
* **No retry / fallback mechanism exists anywhere in this repo.** Required
  design decision (not yet made): per-colour fault isolation (so one bad λ
  doesn't void transactions on the other 59), an upper-layer
  retransmit/re-fetch path, or a mode fallback (degrade the transaction's
  `P` or drop to Mode A) when a lane's overflow rate exceeds a threshold.
  Silently losing compute results is not an acceptable default.

## Orange Team post-task review question

**Embedded verbatim — to be answered explicitly when this story executes, not
assumed away:**

> *"Are we treating 64 λ as merely a router-capacity number, when the actual
> system constraint is the receiver's ability to synchronize, buffer, deskew,
> and reconstruct all those wavelengths?"*

[[TKT-019.1]] proved `gcb_wavelength_router` scales to `N_LAMBDA = 64` as
**pure permutation wiring — 0 logic cells**, which is cheap by construction.
This story's own findings (above) suggest the honest answer is **no, 64 λ is
not "just" a router number** — the router was the easy 5% (wiring); the
deskew/CDC/failure-handling stage is the physically hard, currently
under-specified 95%. That asymmetry is itself a finding this story must state
plainly in its execution, not soften.

**Answered at execution, stated plainly: yes, we were.** The router's
`0 logic cells` at any `N_LAMBDA` measures wiring cost, not system
correctness. Execution confirmed the gap was real in two independent ways:
(1) `gcb_dwdm_deskew` genuinely has **no CDC logic anywhere** — it was built
on an undeclared shared-clock assumption, confirmed by reading the RTL, not
inferred; (2) building and testing the CDC-capable sibling
(`gcb_dwdm_deskew_cdc`) took an order of magnitude more design and
verification effort than TKT-019.1's router parameterisation — a dual-clock
gray-code FIFO, a bounded-wait barrier with a named failure signal, and a
cocotb testbench methodology bug-hunt (below) that the router work never
needed. The receiver's synchronize/buffer/deskew/reconstruct problem is where
this epic's real engineering cost lives; 64 λ as a router-capacity number was
never the hard part.

Per Task 1.4: **no PBG grade was assigned on drafting** (`telemetry_color:

* **Orange (methodology, not a grade):** every number above is either sourced
  to a checked-in artifact ([[GCB-034]], [[GCB-037]], [[TKT-019.1]]) or
  explicitly flagged `pending spec` / `estimate`. The deliverable is a
  **falsifiable characterisation** — a validated skew envelope, a validated
  CDC decision, a validated depth, a validated area/power number, a validated
  failure policy — not a chosen FIFO depth with a retrofitted justification.
* **Green (target, at execution):** `MAX_SKEW_CYCLES` and the CDC architecture
  derived from a cited skew source, not assumed; `NUM_COLORS` scaled to
  `≥ 60` with the validated depth; a stated, testable failure policy (fault
  isolation / retry / mode fallback); the area/power number carried into
  `docs/PPA_burndown.md` and flagged against the GCB-032 wide-bank pattern.
* **Yellow (reject):** picking a "round number" depth (e.g. bumping
  `MAX_SKEW_CYCLES` to 64 because it matches `N_LAMBDA`) without a skew-source
  citation; adding CDC logic "to be safe" without first determining whether
  the fabric even has independent clock domains; treating `overflow` as
  sufficient failure handling because it already exists.
* **Red (reject):** silently dropping the CDC question because the current
  RTL happens to simulate correctly under a single testbench clock; altering
  the 1024 B / ≥ 60 λ contract inputs to make the deskew numbers look better;
  sizing the FIFO from the CD estimate alone when the CDR/electrical term is
  unvalidated and likely dominant.
* **Purple (possible, not claimed):** if the CD-vs-CDR finding holds, it
  reframes where the real cost of this Epic lives — wiring scales for free,
  synchronisation does not — which is a reusable lesson for every later
  TKT-019.x.
