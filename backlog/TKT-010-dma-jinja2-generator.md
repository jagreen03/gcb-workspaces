# Objective

Implement a Python + Jinja2 generator in `gcb-python-orchestrator` that emits
the GDDR7 DMA's parameter package and CSR decode wrapper as **pure
SystemVerilog**, from a single data file that captures
`gcb-wiki/11_gddr7_tensor_dma_architecture.md`'s parameter set and CSR map. This
is the "parameterisation is Jinja2, not an HDL DSL" half of the EDA doctrine
(`gcb-wiki/10` §3) applied to the DMA: the hand-written datapath (`TKT-009`)
stays hand-written; the repetitive `localparam` derivations and the CSR
register file wrapping it are generated and committed.

## Context & Constraints

* **Current State:**
  * `gcb-wiki/10` §3 mandates the shape: banned — Chisel / Amaranth / SpinalHDL
    / Migen / any "describe hardware in language X, emit Verilog" layer.
    Required — Python + Jinja2 emitting standard SV, generated files committed
    with a `DO NOT EDIT — generated by <script> from <source>` banner, no
    constructs only the template understands. Precedent: `gcb-spec/regen.py`
    (one `registers.yaml` -> SV / C++ / Python / TS / Markdown).
  * `gcb-wiki/11` §0 and §7 enumerate what has to be derived / exposed:
    `VEC_BYTES` (from `OPERAND_BITS`), `ROW_STRIDE` (= `K_STEPS * VEC_BYTES`),
    `K_STEPS`, `GRID_DIM`, `N_TILE`, `M_BANDS`, `N_PASSES`, burst length, plus
    the CSR block (`DMA_VEC_BYTES`, `DMA_ROW_STRIDE`, `DMA_GRID_DIM`,
    `DMA_N_TILE`, `DMA_M_BANDS`, `DMA_N_PASSES`, `DMA_B_LAYOUT`, `DMA_CTRL`,
    `DMA_STATUS`, `DMA_IRQ_EN`) with the `UNDERRUN` / `ERR` / `CFG_ERR` /
    `RUNNING` / `A_BUSY` / `B_BUSY` fields.
  * EDA toolchain: the generated SV is lint-checked by Verilator 5 and
    elaborated by Yosys + Surelog/UHDM, same bar as hand-written RTL.
* **Sequencing:** soft-depends on `TKT-009` — the CSR wrapper wraps
  `gcb_tensor_dma_arbiter`, so its port list must be stable before the wrapper
  is finalised. The parameter package can be drafted from Doc 11 alone. This
  ticket is **deferred** behind the active silicon path (`TKT-009`) per the
  Architect; it captures orchestration debt, it does not block the RTL.
* **Constraint:** No new HDL language. The generator is Python; its output is
  standard SystemVerilog (`parameter` / `localparam` / `generate` / `case` — no
  macro soup). Generated files are committed, carry the banner, and re-running
  the generator on an unchanged source produces a **byte-identical** file
  (idempotent, CI-checkable). A checkout without Python still builds.

* **Design notes:**
  * The elaboration guards cannot live in a `package` (SV forbids procedural
    code there — Verilator: "syntax error, unexpected initial"). They are
    emitted into the generated **wrapper's** `initial` block instead; the
    datapath keeps its own copy. Noted in both generated headers.
  * `dma_params.yaml` `derived:` is an ordered list of `{name, expr}` — `expr`
    is a Python expression evaluated in order against the running namespace plus
    `clog2()` / `width()` helpers matching SV `$clog2` semantics
    (`width(n) = 1` for `n<=1`). This keeps the source declarative without a
    second expression language.
  * The wrapper overlays 7 read-only geometry-mirror registers
    (`DMA_VEC_BYTES` … `DMA_B_LAYOUT`, offsets 0x20–0x38) on top of the
    arbiter's own CSR space (0x00–0x10), registered 1-cycle to match the
    arbiter's read latency; `mir_sel_q ? mir_val_q : arb_rdata`. Writes to the
    mirror block are dropped (RO); the arbiter already ignores unknown offsets,
    so `csr_we` passes straight through.
